- 文件版本：0.3
- 建立日期：2026-10-14
- 狀態：初版；包含待確認事項，尚非所有實作決策均已定案
- 用途：作為 AI 開發 Mac 與 Windows App 的主要需求來源

## 建置與 output（2026-10-16 已確認）

本機支援在 macOS、Windows 各自執行相同的建置入口，產物統一放到專案根目錄 `output/`。2026-10-16 最新決策：將 output 排除 Git，規劃透過 GitHub Actions 分別建置兩平台，再以 GitHub Releases 提供下載。Actions 設定已建立，但尚未執行雲端驗證，操作見第 17 節。

```sh
# macOS：在專案根目錄執行
./build
```

```powershell
# Windows PowerShell：在專案根目錄執行
.\build.cmd
```

- Mac：`output/Mac/iPhoneBackUp.app`，一個可開啟的 App bundle；這台電腦產出 Apple Silicon arm64 版。
- Windows：`output/Windows/iPhoneBackUp.exe`，單一可執行檔；需在 Windows 實際建置與驗證，仍需系統 iPhone USB 驅動／服務。
- `BUILD-INFO.json` 記錄實際產物名稱、CPU 架構與封裝檢查結果。
- Mac 預設收集已安裝 Homebrew libimobiledevice 及其依賴與授權；Windows 需先將對應 DLL 與授權放入 `Windows/native/`。可用 `--native-dir` 指定自備元件。
- 先在平台的 `build/` 暫存位置封裝，檢查內附 Qt／Pillow／USB 元件能載入，才發布到 `output/`。這項檢查不會讀取手機或建立備份，也不等於功能驗收。
- 更新成功前保留舊 App；舊版搬至平台 `build/previous/`。若環境不允許搬移，保留原檔，改輸出含 build ID 的新版檔名，實際名稱以 `BUILD-INFO.json` 為準。
- Mac 目前為本機 ad-hoc 簽章，尚未 Developer ID 簽章與公證；Windows 尚未程式簽章。
- 平台原始碼仍放在 `Mac/`、`Windows/`；`output/` 是最新指定的統一成品位置，取代舊的各平台 `dist/` 交付位置。

PyInstaller 必須在各目標系統分別執行，不能以這個本機 build 在 Mac 同時產生 Windows 版。[官方建置說明](https://pyinstaller.org/en/stable/usage.html)

## 1. 產品目的

家人的 iPhone 累積大量照片、影片與語音備忘錄，導致手機容量不足。需要把資料以原始檔匯出到容量足夠的電腦，確認保存完成後，由使用者自行刪除手機上的資料。

既有 Windows 照片匯入工具曾在大量檔案情境下卡住，本產品應特別處理大量清單、介面回應與匯出失敗。不得宣稱改用本產品就必然消除所有 USB、裝置或作業系統錯誤。

本版的「備份」是把指定內容匯出成可取用的原始檔 ZIP，並非具備整機還原能力的 iPhone 系統備份工具。

使用者已再次確認核心操作：App 呈現目前手機內所有照片、影片及內建語音備忘錄，使用者自行選取想保存的內容，再匯出到電腦。2026-10-16 使用者重新確認接受語音備忘錄的暫存本機備份流程：於 App 選擇位置並開始備份，從備份讀取錄音供選取、匯出後清除。此決策取代先前的 USB-only 限制；照片仍使用 USB 直接讀取。不得把備份讀取冒充直接檔案存取。

## 2. 已確認的產品範圍

1. 最終交付 macOS 與 Windows 兩個版本的桌面 App。
2. 開發可先在 Mac 上驗證，再完成 Windows 版本；Mac 版完成不代表整個專案已完成。
3. 使用 USB 連接 iPhone；App 能辨識裝置連接狀態。
4. 左側選單包含「照片＆影片」與「語音備忘錄」。
5. 兩個功能均支援數量／容量統計、全選、個別選取、月份分組及 ZIP 匯出。
6. 照片、影片與錄音均以原始檔匯出為主。
7. 每次匯出是整批成功或整批失敗；不得把部分完成的檔案當成成功成果交付。
8. 遇到未確定且會影響產品行為或資料完整性的問題，AI 應先詢問使用者，取得答案再實作相關部分。
9. 呈現目前手機內所有照片、影片與內建語音備忘錄；不得把只列出部分可存取內容視為已完成此需求。若驗證發現無法完整取得，須說明缺漏範圍與限制，取得使用者對調整方案的確認。

先前純 GitLab Pages 網站、電腦免安裝的構想不再作為本版必要條件。是否發布到 GitLab、是否提供免安裝版本，仍待確認。

## 3. AI 開發規則

- 本文件中的「已確認需求」必須實作，不得擅自縮減為介面展示。
- 「建議」與「待確認」並非使用者已接受的需求；不得直接當成定案。
- 技術限制導致需求不可行時，說明已驗證的限制與可選方案，先詢問使用者，不得偷偷更改功能。
- 可先完成不受待確認事項影響的工作；不得用自行假設替代必要的確認。
- 模擬資料只能用於開發，必須明確標示；不得將模擬裝置連線或假匯出描述為正式功能。
- 保持裝置存取、資料模型、選取／分組、ZIP 匯出與介面分離，以支援兩個平台。
- 已確認技術方案：Python＋PySide6 桌面介面，libimobiledevice 唯讀 USB 存取；清單與匯出在背景執行。此選擇不代表已驗證所有 iOS 版本或內容的可存取性。
- 不得自動刪除或修改 iPhone 上的資料；本版匯出操作只讀取手機內容。

## 5. 共用介面與資料行為

### 已確認需求

- 左側選單可切換「照片＆影片」與「語音備忘錄」。
- 各頁顯示該類別的總數量與總容量。
- 各頁提供全選，以及個別項目選取。
- 清單依月份分組，月份之間有明確分隔線與年月標示。
- 只匯出這次選取的項目。
- 已確認月份規則：依拍攝／錄製日期分組，由新到舊排列；缺少日期集中在「日期未知」，不得用檔案修改時間捏造拍攝／錄製日期。日期來源的涵蓋範圍仍須驗證，時區轉換規則尚待定義。

### 建議待確認

- 額外顯示已選項目的數量與容量。
- 全選後可取消全選；每個月份提供整月選取／取消選取。
- 清單未完成讀取時，統計顯示「計算中」；無法取得容量時標示未知，不能當作 0。
- 讀取清單與匯出在背景進行；大量資料不得阻塞介面操作。
- 未選取項目時不允許啟動匯出。
- 顯示匯出進度、處理數量與取消操作。

## 6. 「照片＆影片」功能

### 已確認需求

1. 呈現目前 iPhone 內所有照片與影片項目清單；完整取得方式須經實機驗證。
2. 計算總數量與總容量。
3. 提供全選按鈕。
4. 圖片項目的左上角有可點選的勾選按鈕。
5. 依月份分隔項目。
6. 依選取項目產生一個 ZIP。
7. 匯出以原始檔為主，不進行格式轉換、縮圖替代、降解析度或重新編碼。
8. 任一必要檔案匯出失敗，整次匯出失敗。

### 建議待確認

- 影片也採相同位置的選取按鈕，並顯示影片標示、時長與容量。
- 拍攝日期來源及時區轉換需進一步驗證與定義；已確認缺失時歸入「日期未知」。
- 無法顯示 HEIC 或其他格式的縮圖時，提供佔位圖及檔名，仍可選取與匯出。

### 已確認多檔素材保存

- 原始素材及可取得的編輯結果／資訊都保留。
- Live Photo 顯示並計數為一個項目，保留照片及配對影片；任一必要組成檔案失敗，整批失敗。配對必須經中繼資料驗證，不得只靠同名猜測。

### 必須釐清的原始檔語意

「原始檔」不代表所有照片型態都只有一個檔案。Live Photo、連拍、RAW＋JPEG、編輯後照片與輔助檔案可能有不同組成。

已確認保存原始素材及可取得的編輯結果／資訊；各型態必要組成的識別與取得方式仍需驗證，不得默認忽略使用者想保存的內容。若 USB 或系統介面提供的是轉換後檔案，必須先驗證並說明，不能標示為符合原始檔要求。

若有內容只在 iCloud 或無法經此讀取方式取得，必須明確呈現限制，不得宣稱已取得手機相簿中的所有項目。

## 7. 「語音備忘錄」功能

### 已確認需求

1. 呈現目前 iPhone 內建「語音備忘錄」的所有錄音清單；完整取得方式須經實機驗證。
2. 計算總數量與總容量。
3. 提供全選與個別選取。
4. 依月份分隔項目。
5. 依選取項目產生一個 ZIP。
6. 匯出以原始錄音檔為主，不重新編碼或只匯出部分錄音。
7. 任一必要檔案匯出失敗，整次匯出失敗。

### 建議待確認

- 清單顯示名稱、錄製日期、時長及容量。
- 錄製日期的中繼資料取得方式待驗證；已確認按錄製日期分月，不以匯出或備份日期代替。

### 裝置存取待驗證

- 不假設語音備忘錄可透過照片讀取介面直接取得。
- 優先驗證 USB 直接取得完整錄音清單與檔案的可行性；不得把需要先建立本機手機備份描述為已確認的必要流程。
- 使用者已接受暫存備份方案；只有在 App 選定位置與容量上限並按下開始後執行。不能僅備份語音，首次暫存仍可能很大。
- 唯讀驗證 USB 媒體目錄及 iOS 授權的 App 目錄介面；若均未開放，須如實標示無法取得，不能把缺漏當成零筆錄音。
- 若備份已加密，確認使用者輸入密碼的流程及支援範圍；不得擅自關閉加密或變更手機備份設定。
- 有剪輯、效果、音層或特殊音訊格式的錄音，已確認保留原始素材及可取得的編輯結果／資訊；其完整取得方式仍需驗證，不能默認用混音輸出取代全部素材。
- 其他錄音 App 暫未列入已確認範圍。

## 8. ZIP 匯出與整批失敗

### 已確認需求

- 每次依使用者所選項目建立 ZIP。
- 「照片＆影片」與「語音備忘錄」各自啟動匯出；跨類別合併 ZIP 並非已確認需求。
- 任一選取項目的必要原始檔無法完整匯出，整次工作失敗。
- 不允許略過失敗檔案後仍回報成功。
- 不刪除、不修改手機原檔。

### 已確認實作契約

1. 使用者選擇輸出位置，固定此次選取清單。
2. 在輸出位置建立本次專用暫存 ZIP，不直接寫入正式成品檔。
3. 逐一讀取並寫入選取項目的所有必要檔案。
4. 關閉 ZIP，核對清單與內容完整性；僅看到 ZIP 檔存在，不代表匯出成功。
5. 所有檢查成功後，將暫存檔改為正式檔名並回報成功。
6. 任一階段失敗或取消，回報整批失敗並清除本次暫存檔。
7. 暫存檔無法清除時，說明路徑與清除失敗原因，不能把它當成成功成品。
8. App 異常退出後，重新啟動能辨識未完成暫存檔，不得誤報成功。

「整批失敗」意味已處理檔案不作為部分成功成果交付。第一版是否每次失敗都全部重傳、是否保留內部暫存以供重試，待確認。

### 大量檔案要求與待確認選項

- 必須支援 ZIP64，避免傳統 ZIP 的容量與檔案數限制。
- 已確認照片、影片、錄音採不額外壓縮的 ZIP 封裝，保留原始內容並減少處理時間。
- ZIP 內建議按 YYYY-MM 分資料夾；確切結構待確認。
- 重名檔案不得覆蓋；檔名保留方式與識別碼規則待確認。
- 檢查輸出檔案系統限制、可用空間與暫存需求；不得只檢查選取檔案總容量而忽略備份、ZIP 開銷與暫存。
- 已存在同名 ZIP 時不得默認覆蓋，應詢問或產生新名稱。
- ZIP 內是否附帶匯出清單，保存原錄製／拍攝日期與檔名對應，待確認。

## 11. 建議開發順序

1. 確認本文件的關鍵待確認事項與技術方案。
2. 在 Mac 驗證 iPhone 連線與原始照片／影片讀取。
3. 提前驗證語音備忘錄取得方式及原始檔完整性。
4. 完成兩類別清單、統計、月份分組與選取。
5. 完成 ZIP 匯出、完整性檢查及整批失敗處理。
6. 以大量資料、拔線、磁碟不足與取消操作測試 Mac 版。
7. 實作 Windows 裝置存取與打包，完成同等實機驗證。

## 12. 驗收條件

- USB 連接並取得必要授權後，能辨識實體 iPhone。
- 兩個功能頁均能列出目前手機內所有對應內容；統計與所列項目一致，並與實機內容核對。未知或不可存取內容有明確說明；若只取得部分內容，不算通過完整清單驗收，除非使用者另行確認調整範圍。
- 全選及個別勾選會正確決定匯出清單；未選取內容不出現在 ZIP。
- 月份分隔符合最終確認的日期規則。
- ZIP 中包含所有選取項目的必要原始檔；格式與內容符合最終確認的原始檔定義。
- 成功 ZIP 可由支援 ZIP64 的工具開啟，照片／影片／錄音可正常取用。
- 讀取錯誤、寫入錯誤、磁碟不足與其他中途故障不會留下被標示成功的部分 ZIP。
- 整批匯出失敗不更動既有成功 ZIP，也不修改手機內容。
- 大量項目情境介面保持回應；數量、容量、耗時與錯誤有實機測試紀錄。
- macOS 與 Windows 各自通過驗收，才算雙平台成品完成。

## 13. 優先詢問使用者的事項

實作相關部分前，優先確認：

1. 語音備忘錄已接受暫存本機備份方案；備份錄音涵蓋範圍、加密備份解密及實機相容性仍須驗證。
